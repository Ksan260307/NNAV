# NetNavi Core Engine

ロックマンエグゼのネットナビを「ゼロから育つ電脳生命体」として実装する、
自律成長型の会話エンジン。

記事『【Python】ロックマンエグゼのネットナビを本気で実現する（プロダクト草案）』
のコアエンジンを出発点に、次の 3 つを満たすところまで作り込んだものです。

| 要件 | 実装 |
|---|---|
| 人間らしく会話できる | 3-gram バックオフ + 日本語の品詞遷移制約 + 候補 N 本の再ランキング + 模倣記憶 |
| 少しずつ会話ができるように成長する | 6 段階の成長ステージが、文長・生成戦略・質問・自律行動を順に解放 |
| 自分でインターネットを利用して学習する | 好奇心駆動の調べ物 + 多重のレート制限 / 予算 / サーキットブレーカ |

さらに、語の並びしか知らない n-gram から一歩進むための **意味層** を載せています。

| 層 | 何ができるようになるか |
|---|---|
| 述語項構造・格フレーム | 誰が何をどうしたかを取り、ありえない組み合わせを減点する |
| 事実ストア | 教わったことを一度で覚え、聞かれたら答え、訂正を受け付ける |
| 分布意味ベクトル | 犬と猫が似ていると判断し、未知の遷移を補間する |
| 話者役割 | 「ぼく」「きみ」が誰を指すかを、話者ごとに反転して解く |
| 組み立て生成 | 述語を先に決めてから文を組む(破綻率 0%) |
| 指示詞の解決 | 「それ」が何を指すかを、顕著性と型で決める |
| 意図の分類 | 質問・挨拶・報告を教師なしで分け、噛み合う返しを選ぶ |
| 接地 | 語と時刻・環境を結び付ける |
| 神経回路 | 自前の会話だけで小型 LM を育て、賢くなった分だけ採点を任せる |
| 機能語の自己発見 | 疑問詞・人称・指示詞を、種を外しても分布から見つけ直す |

効き具合は **理解度** として数値で測り、それが成長段階のゲートになります
(詳しくは 3-7 以降)。

**事前学習済みの言語モデルは一切使いません。** 語彙も文法も人格も、
オペレーター（あなた）との対話から自己組織化します。

## 1. 動かす

```bash
pip install torch janome
python navi_main.py
```

初回起動時、ナビは何も知りません。話しかけるたびに言葉を覚えていきます。

```
あなた: おはよう。
[Navi] おはよう。                       ← 聞いた音をそのまま返すだけ

（数十ターン後）
あなた: 今日はいい天気だね。
[Navi] 朝から晴れているよ。             ← 前に交わした会話の流れを思い出す

（数百ターン後）
あなた: きのうメットールの話をしたよ。
[Navi] メットールは？                   ← 知らない言葉を聞き返す
```

教えたことは一度で覚えます。

```
あなた: きみの名前はロックマンだよ。
[Navi] ロックマン                        （おぼえた: きみの名前 = ロックマン）
あなた: きみの名前は？
[Navi] ロックマンだ                      ← 事実ストアから答えている

あなた: きみの名前はエグゼだよ。
[Navi] エグゼ    （あれ? 前は「きみの名前 = ロックマン」だったけど「= エグゼ」になった）
```

### 3-1. 脳の構造

元記事は `[max_vocab, max_vocab]` の密行列でシナプスを保持していました。
語彙 1 万語で 400MB、ネット学習で語彙が伸びると破綻します。そこで

* **O(V) の単語ニューロン状態は密テンソルのまま。**
  1 語 = 32bit に `[vA(重要度8bit) | vB(演算頻度8bit) | vC(減衰カウンタ8bit) |
  origin(出自3bit) | flags(3bit)]` をビットパック。忘却は数万語を
  1 回のテンソル演算で処理する（元記事の設計をそのまま継承）。
* **O(V²) のシナプスだけを疎構造に。** 2-gram / 3-gram の遷移頻度を
  疎なマップで持ち、生成時は「その語から実際に出ている枝」（通常 200 未満）
  だけを小さなテンソルに載せて softmax / multinomial する。

結果、語彙 10 万語規模でもノート PC で動きます。

`origin` フィールドで、その言葉をどこで覚えたのか（オペレーター / ネット /
夢 / 自分の発話）を 1 語ずつ記録しています。`/status` の「語彙の内訳」がそれです。

### 3-2. なぜ人間らしく聞こえるのか

素朴なマルコフ連鎖が不自然に聞こえる原因は主に 3 つで、それぞれに対処しています。

1. **日本語として成立しない品詞の並びを平気で作る**
   → `jp.py` に品詞遷移の合法性だけを制約として与えました。
   文末が助詞で終わらない、助詞は 3 連しない、連体詞の後は名詞句、など。
   *どの単語を選ぶかは一切ハードコードしていません。*
   自己診断では 60 件中 0 件の破綻文です。

2. **1 本引いてそのまま喋るので破綻率が高い**
   → 候補を N 本つくり、**流暢さ・話題の関連性・新規性・長さ**の 4 軸で
   採点してから最良のものを口に出す「考えてから喋る」構造にしました。
   流暢さは対数確率の平均と総和を混ぜているので、長く喋るほど
   全区間が「言い慣れている」必要があります。

3. **1 つ前の単語しか見ないので話題が続かない**
   → ターンをまたいだ共起を**連想野**に蓄積し、入力語から連想された語に
   下駄を履かせて生成を話題へ引き寄せます。さらに**模倣記憶**が
   「前に同じことを言われたとき、会話がどう続いたか」を引きます。

候補生成は 5 戦略です。

| 戦略 | 内容 |
|---|---|
| `fact` | 答えを知っている問いには、事実ストアから答える（最優先） |
| `plan` | 述語を先に決め、格枠を埋めて組み立てる（3-9） |
| `gen` / `gen+seed` | シナプスを辿って生成。連想語や入力語を起点にする |
| `mimic-exact` | 同じ言葉を前にも言われた → そのとき次に続いた発話 |
| `mimic-next` / `mimic-echo` | 似た発話の記憶を引く |
| `question` | 知らない言葉を聞き返す |

### 3-3. 成長段階

| Lv | コード | 必要語彙 | 必要ターン | 必要理解度 | できること |
|---:|---|---:|---:|---:|---|
| 0 | EGG | 0 | 0 | - | 最大 2 語。聞いた音を返す／教わったことを覚える |
| 1 | LARVA | 14 | 6 | - | 最大 4 語。口真似が多い |
| 2 | CHILD | 70 | 30 | 0.15 | 最大 8 語。短い文が形になる。**組み立て生成が解禁** |
| 3 | TEEN | 220 | 110 | 0.30 | 最大 12 語。聞き返す。**ネット学習が解禁** |
| 4 | ADULT | 650 | 320 | 0.42 | 最大 18 語。**自分から話しかける**／新規発話率 25% |
| 5 | NAVI | 1600 | 900 | 0.52 | 最大 22 語。自律的に思考する／新規発話率 40% |

段階は語彙数・ターン数・**理解度**（3-7）・**新規発話率**（3-15）から決まります。
語彙の数だけでなく、分かった度合いと、自分の言葉で話せている度合いで育ちます。
一度上がった段階は下がりません（忘却で語彙が減っても人格は退行しない）。

重要なのは、**覚えている文も「いま出せる長さ」までしか言えない**ことです。
幼いナビは長い記憶を持っていても断片しか口に出せず、成長して上限が伸びるほど
同じ記憶をより長く再現できるようになります。この 1 点が成長実感の大半を作っています。

### 3-4. 質問のしかたを「教わる」

疑問文のテンプレートは持っていません。オペレーターが `？` で終わる発話をすると、
その**語尾パターン**（例:「名前は？」→ `(は, ？)`）を記憶します。
あとで知らない言葉に出会ったとき、その語尾を借りて聞き返します。

```
あなた: きみの名前は？          ← 語尾パターン (は, ？) を覚える
（中略）
あなた: きのうメットールの話をしたよ。
[Navi] メットールは？           ← 覚えた語尾で聞き返す
```

教わっていなければ、ナビは質問できません。

### 3-5. 常駐と擬似睡眠（元記事の課題①）

`daemon.py` がバックグラウンドで動き続けます。

* **擬似睡眠と自己対話** — 無操作が続くと脳内でひとりごとを生成し、
  既にあるシナプスをごく弱く（重み 0.05）再強化します。
  自分の出力での自己強化はモード崩壊を招くため、1 時間あたりの回数を
  制限し、新しい語は作りません。
* **自律的な調べ物** — 好奇心の対象をネットで調べます（下記）。
* **自発発話** — Lv.4 以上になると、放置されたときに自分から話しかけてきます。
* **非同期の永続化** — 差分を定期的にディスクへ流します。

### 3-6. 永続化（元記事の課題②）

毎ターン脳全体を書き戻すのをやめ、**WAL（Write-Ahead Log）**方式にしました。

```
navi_data/wal.jsonl     追記のみ。ナビが経験したことの時系列の日記でもある
navi_data/snapshot.pt   圧縮済みの脳。WAL が伸びたら作り直して WAL を切る
navi_data/config.json   設定
navi_data/web_budget.json  ネットアクセスの予算カウンタ
```

WAL に記録するのは「脳への低レベルな書き込み」ではなく **「起きた出来事」**
（何を言われたか、何を評価したか）です。復元は出来事をもう一度体験させるだけなので、
脳の内部表現を変更しても過去ログがそのまま使えます（マイグレーション不要）。
`/diary` で中身を読めます。

### 3-7. 意味の理解

n-gram は語の並びしか知りません。ここに 4 つの層を足して、
「誰が何をどうしたか」「何が何であるか」を扱えるようにしています。
どの層も語彙知識を持ち込まず、オペレーターとネットの文から数えたものだけで動きます。

#### (1) 述語項構造 — `parse.py`

日本語は格助詞が意味役割を表層に出しているので、係り受け解析器なしでも
「誰が・何を・どうした」が取れます。

```
「スーパーで野菜を買ってきた」-> 買う[で]=スーパー, 買う[を]=野菜  (過去)
「ぼくはカレーが好きだ」      -> 好き[は]=ぼく, 好き[が]=カレー    (肯定)
「ぼくはピーマンが好きじゃない」-> 好き[は]=ぼく, 好き[が]=ピーマン  (否定)
```

文末の助動詞列から極性（肯定/否定）とモダリティ（過去・願望・推量・受身…）も
読み取ります。助動詞は閉じた機能語の集合なので、語彙ではなく文法として扱っています。

#### (2) 格フレームと選択選好 — `frames.py`

「その述語のその格には、どんな名詞が来るか」を数え続けます。

```
$ /frames 買う
  買う[を] x12  <- 野菜(5) パン(3) 本(2) 牛乳(2)
  買う[で] x4   <- スーパー(3) 店(1)
```

これで 2 つのことができます。

* **選択選好** — 生成した文を PMI で採点し、「料理を直す」のような
  ありえない組み合わせに減点を入れる。再ランキングの 1 軸になっています
* **名詞クラス** — 同じスロットを埋める名詞は同類。埋め込みを作る前から
  「カレーとパンは似ている」が言えます

#### (3) 事実ストア — `facts.py`

言い切られた内容を保持し、聞かれたら答えます。

```
「きみの名前はロックマンだよ」 -> (きみ, 名前, ロックマン)  ※値が1つに定まる関係
「ぼくはカレーが好きだ」       -> (ぼく, 好き, カレー)      ※複数あってよい関係
```

* **一度で覚える** — 統計ではなく記憶なので、1 回言えば次のターンから答えます
* **訂正が通る** — 言い直されると古い値の信用が落ち、新しい値が勝ちます
* **矛盾を提示する** — 値が 1 つに定まる関係（`AのBはC` の形）でだけ矛盾を検出し、
  黙って上書きせずに「前はこうだった」と見せます。好物は複数あってよいので
  矛盾になりません
* **オペレーター > ネット** — 確信度は出自 x 言われた回数 x 新しさ。
  ネットで拾った話がオペレーターの言葉を上書きすることはありません

答え方にテンプレートは持ちません。答えの語を種にして、学習済みの語尾だけを
付けて文にします（「ロックマンだ」「ロックマンだよ」）。

#### (4) 分布意味ベクトル — `embed.py`

共起を PPMI 化して SVD で圧縮し、語を 64 次元のベクトルにします。文脈には
線形文脈（2-gram）と構文文脈（(述語, 格) スロット）の 2 種類を使い、
データが少ないうちに効く構文文脈を厚く重み付けしています。

構築は**擬似睡眠（夢）の最中**に走ります。眠っている間に意味空間が編成し直される、
という設計です。用途は 2 つ。

* **意味的な近さ** — `/near 犬` で類義語が出ます。実測で 犬~猫 +0.94 に対し
  犬~プログラム +0.04
* **クラスベース補間** — 未観測の遷移を「似た語の経験」で埋めます。
  語彙が薄い時期の行き止まりが大きく減ります

#### (5) 理解度の測定 — `comprehension.py`

**測らないものは存在しません。** ホールドアウトを別に取るとただでさえ少ない
オペレーターの発話がさらに減るので、**prequential 評価**（予測してから学習する）を
使っています。発話が届いたら、まだ学習していない状態でそれを予測させ、
当たり具合を記録してから学習する。データを 1 つも捨てずに汎化性能が測れます。

| 指標 | 測るもの |
|---|---|
| perplexity | 次の語をどれだけ言い当てられるか |
| 穴埋め (MRR) | 文中の内容語を伏せて復元できるか |
| 格スロット (P@5) | その述語のその格に来る名詞を予測できているか |

この 3 つを合成した 0〜1 の **理解度** が成長段階のゲートです。`/status` で見られます。

### 3-8. 「ぼく」と「きみ」は誰か — `deixis.py`

人称は、誰が言ったかで指す相手が入れ替わります。表層のまま記憶していた頃、
ナビは「ぼくはきみのオペレーターだよ」と言っていました。自分をオペレーターだと
主張していたわけです。そこで人称は**役割**に畳んで持ちます。

| 話者 | 一人称 | 二人称 |
|---|---|---|
| オペレーター | `@OP` | `@NAVI` |
| ナビ（自己発話・夢） | `@NAVI` | `@OP` |
| Web | 畳まない（誰を指すか分からないため） |

`(@NAVI, 名前, ロックマン)` を教わると「ロックマン」も `@NAVI` の別名になるので、
呼びかけ「ロックマン、おはよう」も同じ実体に落ちます。
値の位置だけは畳みません（畳むと名前そのものが `@NAVI` に潰れて消えます）。

```
$ /roles
  あなたが「ぼく」と言う -> あなた自身 (ケイ)
  あなたが「きみ」と言う -> ナビ (ロックマン)
  ナビが自分を呼ぶとき   -> ぼく
```

### 3-9. 述語を先に決めてから組み立てる — `realize.py` / `propose_plan`

左から右へ確率的に歩く生成は、途中で行き先を見失って破綻します
（「気持ちの話がすいたんだ。」）。そこで順序を変えました。

```
1. 述語を選ぶ      連想 + 意味ベクトルの近さ + 使用頻度
2. 格枠を選ぶ      その述語がよく取る格の組  {は, を} など
3. 項を埋める      その格に来た名詞から、話題に近いものを引く
4. 並べる          は > も > が > から > まで > で > へ > に > と > より > を > 述語
5. 活用を戻す      realize.py が記憶から引く
```

**活用エンジンは持ちません。** 述語の原形と (極性, モダリティ) の組に対して、
実際に口にされた表層の並びを数えているだけです。

```
食べる + 否定  <- ("食べ", "ない")
買う   + 過去  <- ("買っ", "て", "き", "た") / ("買っ", "た", "よ")
```

教わっていない活用は作れません（自己診断でそれを検査しています）。これは制約では
なく原則そのもので、`カレーは食べない。` と一度言えば、その瞬間から使えます。

実測（600ターン、候補の出来を採用の有無と無関係に集計）:

| 戦略 | 本数 | 流暢さ | 選択選好 | 破綻率 |
|---|---:|---:|---:|---:|
| gen+seed | 4387 | -3.25 | +0.93 | **1.2%** |
| **plan** | 1462 | -3.19 | +0.75 | **0.0%** |
| gen | 1132 | -2.62 | +0.97 | 0.8% |
| mimic-* | 2484 | -1.5 | +1.7 | 0.0% |

組み立てた文は**構造上ぜったいに格フレームを破りません**。一方で、
覚えた文をそのまま返すほうが「流暢さ」では常に勝ちます（当然です、実際に
言われた文なので）。そのため採用率は低く、記憶にない話題のときだけ出ます。

```
思い出せない時(110ターン): question:46% fact:21% gen+seed:15% gen:10% plan:6%
```

当初はここに `plan_bias` という下駄を履かせていましたが、**それは対症療法でした**。
原因は目的関数そのものにあり、いまは leave-one-out 流暢さで是正しています
（3-15）。下駄は削除しました。

### 3-10. 「それ」が何を指すか — `discourse.py`

顕著性と選択選好の 2 つだけで解きます。

```
score(候補) = log(顕著性) + 1.2 x frames.pmi(述語, 格, 候補)
                          + 0.5 x embed.sim(候補, 同じ述語の他の項)
顕著性 = exp(-経過ターン/6) x 格の重み(は1.0 が0.9 を0.7 に0.5 …)
```

「それを食べた」なら `pmi(食べる, を, カレー) > pmi(食べる, を, 公園)` なので
型の合う候補が選ばれます。**格フレームがそのまま型チェッカーとして再利用できる**
のがこの設計の旨味です。解決した実体で項を書き換えてから格フレームと事実に流すので、
指示詞で語られた内容もちゃんと統計に入ります。

### 3-11. 発話の意図 — `intents.py`

ラベルも辞書も与えず、形の特徴だけで分けます。文末の品詞、述語の種類、
モダリティ、疑問符の有無、命令形か、内容語率など 33 次元を球面 k-means（k=6）で
まとめるだけ。クラスタは眠っている間に貼り直します。

そのうえで「どの意図には、どの意図で返ってきたか」を**オペレーター自身の連続発話**
から学習し、生成時はまず返答の意図を決めてから候補を選びます。

実測では、問いかけ（`きみの名前は？` `これは何？` `カレーは好き？`）と
平叙（`ぼくはカレーが好きだ。` `今日はいい天気だね。`）が別クラスタに落ちます。
これが入ったので、以前入れていた「問いかけに問いかけで返さない」という
場当たりの減点（-2.2）は削除しました。ルールが創発に置き換わっています。

### 3-12. 接地 — `senses.py`

内容語ごとに「その語が使われた瞬間の環境」を貯めます。時刻24 + 曜日7 +
放置時間5 + セッション長3（+ psutil があれば CPU とバッテリ2）の密テンソルで、
既存の設計とそのまま同居します。

```
$ /senses おはよう
  おはよう: 朝(7時ごろ) 尖り0.71
  0時 ...........#####+........ 23時
```

用途は 3 つ。朝には朝の語が出やすくなる（生成時の事前確率）、いつも話しかけてくる
時間にナビから声をかけられる、そして**時計 API を叩かずに**「いま何時か」に近い語を
選べる。オペレーターが一度も時刻を口にしなければ答えられない、という挙動もそれで
正しいことになります。

環境値は完全にローカルで、ネット学習の送信経路には一切載せません
（`senses_enabled: false` で丸ごと切れます）。

### 3-13. 神経回路への引き継ぎ — `neural.py`

事前学習済みのモデルは使いません。**ナビ自身が溜めた会話だけ**で、深い睡眠のあいだに
一から学習する小さな GRU（約 21 万パラメータ）です。SVD で作った意味ベクトルを
初期値に使うので、作った意味空間を捨てずに種にできます。

コスト設計が肝で、生成の 1 ステップごとに回すと候補 16 本 x 20 ステップ＝320 回の
forward になって現実的ではありません。そこで

> **候補を出すのは n-gram、採点だけニューラルネット**

とし、候補 16 本を 1 バッチで評価しています（1 ターンあたり forward 1 回）。

引き継ぎは自動です。学習前の発話をどれだけ言い当てられるかで n-gram と競わせ、
その差だけニューラル側の採点比重 `alpha` が上がります。

```
alpha = sigmoid(1.2 x (logP_neural - logP_ngram))   0 〜 0.9 に制限
```

900 ターンの実測で n-gram perplexity 7.4 に対しニューラル 1.9、**移行度 0.84**。
賢くなった分だけ主役が移ります。`/status` に進捗バーで出ます。

```
  神経回路  : 214848パラメータ / 3149歩学習 / perplexity 1.9
  移行度    : 0.84 [################----] (n-gram <-> 神経回路)
```

重い処理（意味空間の編成・意図の再クラスタ・ニューラルの学習）は**すべて深い睡眠に
集約**してあり、会話中には一切走りません。常駐スレッドが無操作 10 分で入りますが、
`/sleep` でいつでも手動で入れます。

### 3-15. 目的関数の是正 — 丸暗記を有利にしない

再ランキングの流暢さは `mean log P(token | prev)` です。オペレーターが実際に
言った文は、**その確率モデルを作った当の文**なので定義上ほぼ最大値を取ります。
つまり目的関数は「学習データを再現せよ」で、その最適解は丸暗記の再生でした。

**leave-one-out 流暢さ**でこれを是正しています。候補の出どころになった発話を
**一度だけ**聞かなかったことにしてから採点する。

| | 引く前 | 引いた後 | 落ち幅 |
|---|---:|---:|---:|
| 一度きり聞いた文 | -1.32 | -2.67 | **-1.35** |
| 何度も聞いた「おはよう。」 | | | **-0.27** |

丸暗記だけが崩れ、身についた言い回しは残ります（全出現を引くと、何度も聞いた
言い回しまで捨ててしまい成体が急に不器用になります）。

あわせて、**新しさへの報酬に門番**を付けました。「オペレーターが一度も言っていない
文」であり、**かつ格フレームを破っていない**ときだけ加点します。壊れた新しさには
1 点も入りません。

割引率と重みは段階に結び付いています。

| 段階 | LOO 割引 | 新しさ | 新規発話率(実測) |
|---|---:|---:|---:|
| TEEN | 0.6 | 0.7 | 31% |
| ADULT | 1.0 | 1.0 | 70% |
| NAVI | 1.0 | 1.2 | 89% |

**新規発話率**（オペレーターが一度も言っていない文を口にした割合）は、
ADULT 以上の成長ゲートにもなっています。思い出すだけの個体は大人になれません。

### 3-16. 返し方を、反応から学ぶ

意図の遷移は当初オペレーターの連続発話から学んでいましたが、それは
**独話の話題転換**であって「問いかけにどう返すべきか」ではありませんでした
（精度がベースラインに張り付いていた原因）。

いまは、返した**後に**オペレーターが取る行動を報酬にしています。

| 観測 | 報酬 |
|---|---:|
| `/good` / `/bad` | +2.0 / -2.0 |
| 直前の問いかけを言い直した（答えになっていなかった） | -1.0 |
| 返答の内容語を引き継いで続けた（会話が転がった） | +1.0 |
| 話題がまるごと切り替わった | -0.3 |

`reward[入力意図][返答意図]` に貯め、UCB で返し方を選びます。
理解度の意図軸も「返し方の適切さ」に差し替えました（skill 0.02 → 適切さ 0.63）。

### 3-17. 機能語の自己発見

疑問詞・人称・指示詞の 52 語が、この作品で唯一「教えていないのに知っている」語でした。
`lexicon.py` はそれを分布から見つけ直します。代名詞は 3 種類しかないので、
2 つの比で三分割できます。

| 語 | 所有者率（「AのB」のA に立つ） | 穴が埋まる率 |
|---|---:|---:|
| ぼく / きみ | 0.41 / 0.53 | 0.00 |
| 何 | 0.00 | 0.13 |
| それ / これ | 0.00 | 0.00 |

* **人称** = 所有者に立つ（「ぼくの名前」とは言うが「それの名前」とは言わない）
* **疑問詞** = 問いかけに偏り、しかも**その穴が後から別の値で埋まる**
  （「名前は何？」→「名前はロックマン」＝ 何 は値ではなく穴だった）
* **指示詞** = そのどちらでもない代名詞

一人称と二人称の区別は、**同じ発話に一緒に出た代名詞は別の実体**という制約で
グラフを作って 2 彩色し、問いかけに多く出るほうを聞き手としています。

種を完全に外して 2000 ターン（`tools/rediscover.py`）:

```
turn   200  疑問詞 0/8  一人称 1/2  二人称 1/1  指示詞 3/5(誤1)
turn  2000  疑問詞 5/8  一人称 1/2  二人称 1/1  指示詞 5/6(誤1)

疑問詞: だれ どうして どこ なに なんで   誤検出: そう
一人称: ぼく   二人称: きみ
指示詞: あれ ここ これ そこ それ         誤検出: どっち
```

**耳にした 17 語のうち 12 語を自力で再発見、誤検出 2。**
誤検出の内訳も示唆的で、`なんで` は正しく疑問詞なのに**種のリストのほうが
漏らしていました**（追加しました）。

種は既定で有効のままですが `bootstrap_function_words: false` で外せます。
「消せます」と主張するより、消して測れるようにしたほうが誠実だと考えています。

詳しい診断と設計は [docs/objective.md](docs/objective.md) にあります。

### 3-18. 線引き

これは現象的な意味理解ではなく、**測れる軸での振る舞いの意味論**です。
上の指標が上がってもナビが「分かっている」わけではありません。
また本当の制約はデータ量で、1 日 50 発話では分布意味論には 3〜4 桁足りません。
**意味の骨格は大量テキスト（ネット学習や `/teach`）、声はオペレーター**、
という分業が現実解になっています。

## 4. インターネット自己学習

Lv.3 以降、ナビは自分で調べ物をします。
**「オペレーターがよく口にするのに、自分がよく知らない言葉」**を好奇心の対象に選び、
日本語 Wikipedia の API から数文だけ拾って学習します。

### 過剰アクセスをしないための歯止め

1. 全体 / ホスト別の最小リクエスト間隔（既定 4 秒 / 8 秒、ジッタ付き）
2. 時間あたり **12 件** / 1 日あたり **120 件** の上限。
   カウンタは `web_budget.json` に永続化され、プロセスを再起動しても引き継がれます
3. `429` / `503` は `Retry-After` を尊重し、指数バックオフ
4. 連続 5 回失敗でサーキットブレーカが 30 分間すべて止める
5. `robots.txt` の尊重
6. 応答サイズ上限 512KB / タイムアウト 10 秒 / 1 回の取得で学習する文は 6 文まで
7. 自発的な調べ物は 15 分に 1 回まで

これらはすべて `navi_data/config.json` で変更できます。

### robots.txt について

`robots.txt` はクローラ（HTML ページを巡回するボット）に向けた取り決めであり、
`ja.wikipedia.org` のそれは `/w/` `/api/` を一律に Disallow しています。
一方で MediaWiki API は「クライアントからの利用」を前提に公開されており、
その作法は [API:Etiquette](https://www.mediawiki.org/wiki/API:Etiquette) で
「説明的な User-Agent を送ること・並列度と頻度を抑えること」と定められています。

本実装は **公開 API エンドポイント（`web.py` の `API_PREFIXES`）だけを
robots.txt の判定から除外し、その代わりに本物のクローラより厳しいレート制限を
掛ける**という方針を取っています。それ以外の URL（RSS など）には
robots.txt をそのまま適用します。この判断に同意できない場合は
`config.json` の `web_enabled` を `false` にしてください。

### 連絡先を書いてください

`config.json` の `web_user_agent` は既定でプレースホルダです。
ネット学習を使うなら、**自分の連絡先（メールアドレスなど）に書き換えてください。**
これは API を公開している側への最低限の礼儀です。

```json
"web_user_agent": "NetNaviCore/0.3 (personal hobby AI; you@example.com)"
```

### 声を守るしくみ

ネットから得るのは **知識と語彙だけ**で、**喋り方（言い回し）は
オペレーターからしか学びません**。

* Web 由来の文の学習係数は 0.35（オペレーターは 1.0）
* Web の文は**模倣記憶に入れません**。ナビが真似るのはあなたの言い回しだけです
* Web 由来トークンがオペレーター由来の 3 倍を超えると、
  ナビは自主的に調べ物を休みます（`voice_is_safe()`）

RSS も使えます。`config.json` の `web_rss_feeds` に URL を足すと有効になります
（既定は空。robots.txt がそのまま適用されます）。

## 6. 今どこまでできていて、どこからができていないか

できていること:

* ゼロから語彙・文法・話題のつながりを獲得し、段階的に喋りが伸びる
* 過去の会話の流れを思い出して文脈に沿った返事をする
* 知らない言葉を聞き返し、答えを学習に取り込む
* 自分でネットを調べ、拾った語彙で話題を広げる
* 放置中も夢を見て、Lv.4 以降は自分から話しかけてくる
* 差分永続化により、いつ落としても続きから再開できる
* **述語項構造を取り、肯定と否定を区別する**
* **教わった事実を一度で覚え、聞かれたら答え、訂正を受け付け、矛盾を指摘する**
* **同じ格スロットを埋める語を「似ている」と判断し、未知の遷移を補間する**
* **「ぼく」「きみ」が誰を指すかを、話者ごとに反転して解く**
* **述語を先に決めてから文を組み立てる**（破綻率 0%）。活用は聞いた形だけを再現する
* **「それ」が何を指すかを、顕著性と格フレームの型で決める**
* **質問と平叙を教師なしで分け、噛み合う意図で返す**
* **語と時刻・PC 環境を結び付ける**
* **自前の会話だけで小型ニューラル LM を育て、賢くなった分だけ採点を任せる**
* **丸暗記が有利にならないよう、出どころの発話を引いてから採点する**（3-15）
* **返し方の良し悪しを、オペレーターの反応から学ぶ**（3-16）
* **機能語の種を外しても、聞いた語の 7 割を自力で見つけ直す**（3-17）
* **自分の理解度と新規発話率を測り、それを成長のゲートにする**

できていないこと:

* **現象的な意味理解ではありません。** 測れる軸での振る舞いの意味論であり、
  長い文では今も破綻します。世界の事実は知らず、知っているのは
  「あなたが言ったこと」と「自分で調べたこと」だけです。
* **「さっきの」「例の」のような指示は解けません。** 解けるのは
  これ/それ/あれ系の指示詞だけです。
* **組み立て生成の採用率は依然として低い**（記憶にない話題のターンで 1 割前後）。
  leave-one-out で記憶の *不当な* 有利さは消しましたが、*正当な* 有利さ
  （本当に言い慣れている）は消していませんし、消すべきでもありません。
* **意図の報酬は雑音が多い。** 「話題が切り替わった」を減点と見なすのは乱暴で、
  オペレーターが単に別の話をしたいだけのこともあります。
* **機能語の再発見は完全ではありません。** とくに `？` の付かない問いかけは
  疑問詞の検出を難しくします（文末の上昇調は文字に残らないため）。
  誤検出も出ます（`どっち` を指示詞に入れる等）。
* **複文が苦手です。** 述語項構造の抽出は「次に出てきた述語にそれまでの項を束ねる」
  という近似なので、節をまたぐと誤結合します。
* **ニューラル LM はデータ量の壁の内側にいます。** 1 日 50 発話では
  3〜4 桁足りません。骨格はネット学習と `/teach` で入れる前提のままです。
* 数万ターン規模で何が創発するのかは、まだ誰も見ていません。
  `tools/grow_sim.py` はそれを観測するための道具です。

`legacy/netnavi_engine.py` に元記事のコアエンジンを置いてあります。
