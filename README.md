# NetNavi Core Engine

ロックマンエグゼのネットナビを「ゼロから育つ電脳生命体」として実装する、
自律成長型の会話エンジン。

記事『【Python】ロックマンエグゼのネットナビを本気で実現する（プロダクト草案）』
のコアエンジンを出発点に、次の 3 つを満たすところまで作り込んだものです。

| 要件 | 実装 |
|---|---|
| 人間らしく会話できる | 3-gram バックオフ + 日本語の品詞遷移制約 + 候補 N 本の再ランキング + 模倣記憶 |
| 少しずつ会話ができるように成長する | 6 段階の成長ステージが、文長・生成戦略・質問・自律行動を順に解放 |
| 自分でインターネットを利用して学習する | 好奇心駆動の調べ物 + 多重のレート制限 / 予算 / サーキットブレーカ |

さらに、語の並びしか知らない n-gram から一歩進むための **意味層** を載せています。
述語項構造・格フレーム・事実ストア・分布意味ベクトルの 4 つで、
「誰が何をどうしたか」「何が何であるか」を扱い、その効き具合を **理解度** として
数値で測ります (詳しくは 3-7)。

**事前学習済みの言語モデルは一切使いません。** 語彙も文法も人格も、
オペレーター（あなた）との対話から自己組織化します。

## 1. 動かす

```bash
pip install torch janome
python navi_main.py
```

初回起動時、ナビは何も知りません。話しかけるたびに言葉を覚えていきます。

```
あなた: おはよう。
[Navi] おはよう。                       ← 聞いた音をそのまま返すだけ

（数十ターン後）
あなた: 今日はいい天気だね。
[Navi] 朝から晴れているよ。             ← 前に交わした会話の流れを思い出す

（数百ターン後）
あなた: きのうメットールの話をしたよ。
[Navi] メットールは？                   ← 知らない言葉を聞き返す
```

教えたことは一度で覚えます。

```
あなた: きみの名前はロックマンだよ。
[Navi] ロックマン                        （おぼえた: きみの名前 = ロックマン）
あなた: きみの名前は？
[Navi] ロックマンだ                      ← 事実ストアから答えている

あなた: きみの名前はエグゼだよ。
[Navi] エグゼ    （あれ? 前は「きみの名前 = ロックマン」だったけど「= エグゼ」になった）
```

### よく使うオプション

```bash
python navi_main.py --no-web            # ネット学習を切って起動
python navi_main.py --no-daemon         # 常駐スレッドを切って起動
python navi_main.py --teach mylog.txt   # テキストを1行1発話として一括で教える
python navi_main.py --data-dir navi2    # 別の個体を育てる
```

```

  brain.py         単語ニューロン(密テンソル) + シナプス(疎) + 連想野 + 模倣記憶
  generate.py      候補生成 5 戦略 と 再ランキング
  growth.py        成長段階と、段階ごとの「できること」
  emotion.py       気分(元気・好奇心・親密度・機嫌)
  web.py           インターネット自己学習とレート制限
  daemon.py        常駐スレッド(擬似睡眠・調べ物・自発発話・非同期永続化)
  store.py         WAL + スナップショット
  navi.py          本体
  cli.py           コンソール
  --- 意味層 ---
  parse.py         述語項構造・極性・モダリティの抽出
  frames.py        格フレームと選択選好(どの格にどんな名詞が来るか)
  facts.py         事実ストア(言い切られた内容の保持・照会・矛盾検出)
  embed.py         分布意味ベクトル(PPMI + SVD)とクラスベース補間
  comprehension.py 理解度の測定(prequential 評価)
```

### 3-1. 脳の構造

元記事は `[max_vocab, max_vocab]` の密行列でシナプスを保持していました。
語彙 1 万語で 400MB、ネット学習で語彙が伸びると破綻します。そこで

* **O(V) の単語ニューロン状態は密テンソルのまま。**
  1 語 = 32bit に `[vA(重要度8bit) | vB(演算頻度8bit) | vC(減衰カウンタ8bit) |
  origin(出自3bit) | flags(3bit)]` をビットパック。忘却は数万語を
  1 回のテンソル演算で処理する（元記事の設計をそのまま継承）。
* **O(V²) のシナプスだけを疎構造に。** 2-gram / 3-gram の遷移頻度を
  疎なマップで持ち、生成時は「その語から実際に出ている枝」（通常 200 未満）
  だけを小さなテンソルに載せて softmax / multinomial する。

結果、語彙 10 万語規模でもノート PC で動きます。

`origin` フィールドで、その言葉をどこで覚えたのか（オペレーター / ネット /
夢 / 自分の発話）を 1 語ずつ記録しています。`/status` の「語彙の内訳」がそれです。

### 3-2. なぜ人間らしく聞こえるのか

素朴なマルコフ連鎖が不自然に聞こえる原因は主に 3 つで、それぞれに対処しています。

1. **日本語として成立しない品詞の並びを平気で作る**
   → `jp.py` に品詞遷移の合法性だけを制約として与えました。
   文末が助詞で終わらない、助詞は 3 連しない、連体詞の後は名詞句、など。
   *どの単語を選ぶかは一切ハードコードしていません。*
   自己診断では 60 件中 0 件の破綻文です。

2. **1 本引いてそのまま喋るので破綻率が高い**
   → 候補を N 本つくり、**流暢さ・話題の関連性・新規性・長さ**の 4 軸で
   採点してから最良のものを口に出す「考えてから喋る」構造にしました。
   流暢さは対数確率の平均と総和を混ぜているので、長く喋るほど
   全区間が「言い慣れている」必要があります。

3. **1 つ前の単語しか見ないので話題が続かない**
   → ターンをまたいだ共起を**連想野**に蓄積し、入力語から連想された語に
   下駄を履かせて生成を話題へ引き寄せます。さらに**模倣記憶**が
   「前に同じことを言われたとき、会話がどう続いたか」を引きます。

候補生成は 5 戦略です。

| 戦略 | 内容 |
|---|---|
| `fact` | 答えを知っている問いには、事実ストアから答える（最優先） |
| `gen` / `gen+seed` | シナプスを辿って生成。連想語や入力語を起点にする |
| `mimic-exact` | 同じ言葉を前にも言われた → そのとき次に続いた発話 |
| `mimic-next` / `mimic-echo` | 似た発話の記憶を引く |
| `question` | 知らない言葉を聞き返す |

### 3-3. 成長段階

| Lv | コード | 必要語彙 | 必要ターン | 必要理解度 | できること |
|---:|---|---:|---:|---:|---|
| 0 | EGG | 0 | 0 | - | 最大 2 語。聞いた音を返す／教わったことを覚える |
| 1 | LARVA | 14 | 6 | - | 最大 4 語。口真似が多い |
| 2 | CHILD | 70 | 30 | 0.15 | 最大 8 語。短い文が形になる |
| 3 | TEEN | 220 | 110 | 0.30 | 最大 12 語。聞き返す。**ネット学習が解禁** |
| 4 | ADULT | 650 | 320 | 0.42 | 最大 18 語。**自分から話しかける** |
| 5 | NAVI | 1600 | 900 | 0.52 | 最大 22 語。自律的に思考する |

段階は語彙数・ターン数・**理解度**（3-7）から決まります。
語彙の数だけでなく、分かった度合いで育つようにしてあります。
一度上がった段階は下がりません（忘却で語彙が減っても人格は退行しない）。

重要なのは、**覚えている文も「いま出せる長さ」までしか言えない**ことです。
幼いナビは長い記憶を持っていても断片しか口に出せず、成長して上限が伸びるほど
同じ記憶をより長く再現できるようになります。この 1 点が成長実感の大半を作っています。

### 3-4. 質問のしかたを「教わる」

疑問文のテンプレートは持っていません。オペレーターが `？` で終わる発話をすると、
その**語尾パターン**（例:「名前は？」→ `(は, ？)`）を記憶します。
あとで知らない言葉に出会ったとき、その語尾を借りて聞き返します。

```
あなた: きみの名前は？          ← 語尾パターン (は, ？) を覚える
（中略）
あなた: きのうメットールの話をしたよ。
[Navi] メットールは？           ← 覚えた語尾で聞き返す
```

教わっていなければ、ナビは質問できません。

### 3-5. 常駐と擬似睡眠（元記事の課題①）

`daemon.py` がバックグラウンドで動き続けます。

* **擬似睡眠と自己対話** — 無操作が続くと脳内でひとりごとを生成し、
  既にあるシナプスをごく弱く（重み 0.05）再強化します。
  自分の出力での自己強化はモード崩壊を招くため、1 時間あたりの回数を
  制限し、新しい語は作りません。
* **自律的な調べ物** — 好奇心の対象をネットで調べます（下記）。
* **自発発話** — Lv.4 以上になると、放置されたときに自分から話しかけてきます。
* **非同期の永続化** — 差分を定期的にディスクへ流します。

### 3-6. 永続化（元記事の課題②）

毎ターン脳全体を書き戻すのをやめ、**WAL（Write-Ahead Log）**方式にしました。

```
navi_data/wal.jsonl     追記のみ。ナビが経験したことの時系列の日記でもある
navi_data/snapshot.pt   圧縮済みの脳。WAL が伸びたら作り直して WAL を切る
navi_data/config.json   設定
navi_data/web_budget.json  ネットアクセスの予算カウンタ
```

WAL に記録するのは「脳への低レベルな書き込み」ではなく **「起きた出来事」**
（何を言われたか、何を評価したか）です。復元は出来事をもう一度体験させるだけなので、
脳の内部表現を変更しても過去ログがそのまま使えます（マイグレーション不要）。
`/diary` で中身を読めます。

### 3-7. 意味の理解

n-gram は語の並びしか知りません。ここに 4 つの層を足して、
「誰が何をどうしたか」「何が何であるか」を扱えるようにしています。
どの層も語彙知識を持ち込まず、オペレーターとネットの文から数えたものだけで動きます。

#### (1) 述語項構造 — `parse.py`

日本語は格助詞が意味役割を表層に出しているので、係り受け解析器なしでも
「誰が・何を・どうした」が取れます。

```
「スーパーで野菜を買ってきた」-> 買う[で]=スーパー, 買う[を]=野菜  (過去)
「ぼくはカレーが好きだ」      -> 好き[は]=ぼく, 好き[が]=カレー    (肯定)
「ぼくはピーマンが好きじゃない」-> 好き[は]=ぼく, 好き[が]=ピーマン  (否定)
```

文末の助動詞列から極性（肯定/否定）とモダリティ（過去・願望・推量・受身…）も
読み取ります。助動詞は閉じた機能語の集合なので、語彙ではなく文法として扱っています。

#### (2) 格フレームと選択選好 — `frames.py`

「その述語のその格には、どんな名詞が来るか」を数え続けます。

```
$ /frames 買う
  買う[を] x12  <- 野菜(5) パン(3) 本(2) 牛乳(2)
  買う[で] x4   <- スーパー(3) 店(1)
```

これで 2 つのことができます。

* **選択選好** — 生成した文を PMI で採点し、「料理を直す」のような
  ありえない組み合わせに減点を入れる。再ランキングの 1 軸になっています
* **名詞クラス** — 同じスロットを埋める名詞は同類。埋め込みを作る前から
  「カレーとパンは似ている」が言えます

#### (3) 事実ストア — `facts.py`

言い切られた内容を保持し、聞かれたら答えます。

```
「きみの名前はロックマンだよ」 -> (きみ, 名前, ロックマン)  ※値が1つに定まる関係
「ぼくはカレーが好きだ」       -> (ぼく, 好き, カレー)      ※複数あってよい関係
```

* **一度で覚える** — 統計ではなく記憶なので、1 回言えば次のターンから答えます
* **訂正が通る** — 言い直されると古い値の信用が落ち、新しい値が勝ちます
* **矛盾を提示する** — 値が 1 つに定まる関係（`AのBはC` の形）でだけ矛盾を検出し、
  黙って上書きせずに「前はこうだった」と見せます。好物は複数あってよいので
  矛盾になりません
* **オペレーター > ネット** — 確信度は出自 x 言われた回数 x 新しさ。
  ネットで拾った話がオペレーターの言葉を上書きすることはありません

答え方にテンプレートは持ちません。答えの語を種にして、学習済みの語尾だけを
付けて文にします（「ロックマンだ」「ロックマンだよ」）。

#### (4) 分布意味ベクトル — `embed.py`

共起を PPMI 化して SVD で圧縮し、語を 64 次元のベクトルにします。文脈には
線形文脈（2-gram）と構文文脈（(述語, 格) スロット）の 2 種類を使い、
データが少ないうちに効く構文文脈を厚く重み付けしています。

構築は**擬似睡眠（夢）の最中**に走ります。眠っている間に意味空間が編成し直される、
という設計です。用途は 2 つ。

* **意味的な近さ** — `/near 犬` で類義語が出ます。実測で 犬~猫 +0.94 に対し
  犬~プログラム +0.04
* **クラスベース補間** — 未観測の遷移を「似た語の経験」で埋めます。
  語彙が薄い時期の行き止まりが大きく減ります

#### (5) 理解度の測定 — `comprehension.py`

**測らないものは存在しません。** ホールドアウトを別に取るとただでさえ少ない
オペレーターの発話がさらに減るので、**prequential 評価**（予測してから学習する）を
使っています。発話が届いたら、まだ学習していない状態でそれを予測させ、
当たり具合を記録してから学習する。データを 1 つも捨てずに汎化性能が測れます。

| 指標 | 測るもの |
|---|---|
| perplexity | 次の語をどれだけ言い当てられるか |
| 穴埋め (MRR) | 文中の内容語を伏せて復元できるか |
| 格スロット (P@5) | その述語のその格に来る名詞を予測できているか |

この 3 つを合成した 0〜1 の **理解度** が成長段階のゲートです。`/status` で見られます。

#### 線引き

これは現象的な意味理解ではなく、**測れる軸での振る舞いの意味論**です。
上の指標が上がってもナビが「分かっている」わけではありません。
また本当の制約はデータ量で、1 日 50 発話では分布意味論には 3〜4 桁足りません。
**意味の骨格は大量テキスト（ネット学習や `/teach`）、声はオペレーター**、
という分業が現実解になっています。

## 4. インターネット自己学習

Lv.3 以降、ナビは自分で調べ物をします。
**「オペレーターがよく口にするのに、自分がよく知らない言葉」**を好奇心の対象に選び、
日本語 Wikipedia の API から数文だけ拾って学習します。

### 過剰アクセスをしないための歯止め

1. 全体 / ホスト別の最小リクエスト間隔（既定 4 秒 / 8 秒、ジッタ付き）
2. 時間あたり **12 件** / 1 日あたり **120 件** の上限。
   カウンタは `web_budget.json` に永続化され、プロセスを再起動しても引き継がれます
3. `429` / `503` は `Retry-After` を尊重し、指数バックオフ
4. 連続 5 回失敗でサーキットブレーカが 30 分間すべて止める
5. `robots.txt` の尊重
6. 応答サイズ上限 512KB / タイムアウト 10 秒 / 1 回の取得で学習する文は 6 文まで
7. 自発的な調べ物は 15 分に 1 回まで

これらはすべて `navi_data/config.json` で変更できます。

### robots.txt について

`robots.txt` はクローラ（HTML ページを巡回するボット）に向けた取り決めであり、
`ja.wikipedia.org` のそれは `/w/` `/api/` を一律に Disallow しています。
一方で MediaWiki API は「クライアントからの利用」を前提に公開されており、
その作法は [API:Etiquette](https://www.mediawiki.org/wiki/API:Etiquette) で
「説明的な User-Agent を送ること・並列度と頻度を抑えること」と定められています。

本実装は **公開 API エンドポイント（`web.py` の `API_PREFIXES`）だけを
robots.txt の判定から除外し、その代わりに本物のクローラより厳しいレート制限を
掛ける**という方針を取っています。それ以外の URL（RSS など）には
robots.txt をそのまま適用します。この判断に同意できない場合は
`config.json` の `web_enabled` を `false` にしてください。

### 連絡先を書いてください

`config.json` の `web_user_agent` は既定でプレースホルダです。
ネット学習を使うなら、**自分の連絡先（メールアドレスなど）に書き換えてください。**
これは API を公開している側への最低限の礼儀です。

```json
"web_user_agent": "NetNaviCore/0.3 (personal hobby AI; you@example.com)"
```

### 声を守るしくみ

ネットから得るのは **知識と語彙だけ**で、**喋り方（言い回し）は
オペレーターからしか学びません**。

* Web 由来の文の学習係数は 0.35（オペレーターは 1.0）
* Web の文は**模倣記憶に入れません**。ナビが真似るのはあなたの言い回しだけです
* Web 由来トークンがオペレーター由来の 3 倍を超えると、
  ナビは自主的に調べ物を休みます（`voice_is_safe()`）

RSS も使えます。`config.json` の `web_rss_feeds` に URL を足すと有効になります
（既定は空。robots.txt がそのまま適用されます）。

## 5. 調整する

`navi_data/config.json` の主な項目:

| 項目 | 既定 | 意味 |
|---|---:|---|
| `w_operator` / `w_web` / `w_dream` | 1.0 / 0.35 / 0.05 | 学習係数 |
| `synapse_decay` / `synapse_prune` | 0.995 / 0.08 | 忘却の速さ |
| `decay_every_turns` | 4 | 何ターンごとに忘却するか |
| `base_temperature` / `mutation_rate` | 0.85 / 0.05 | 発話の奔放さ |
| `semantics_enabled` | true | 意味層（格フレーム・事実・意味ベクトル）ごと切る |
| `class_backoff` | 0.35 | 未観測の遷移を似た語の経験で埋める強さ |
| `frame_weight` / `semantic_weight` | 0.9 / 1.3 | 選択選好・意味的話題一致の採点重み |
| `fact_answer_bias` | 2.6 | 知っている事実で答えるときの下駄 |
| `embed_dim` / `embed_rebuild_turns` | 64 / 150 | 意味ベクトルの次元と再編成間隔 |
| `use_question_words` | true | 疑問詞の閉じた語彙を使うか |
| `web_max_per_hour` / `web_max_per_day` | 12 / 120 | ネットアクセス上限 |
| `dream_idle_sec` / `proactive_idle_sec` | 90 / 240 | 何秒放置で夢／自発発話 |
| `max_vocab` / `max_edges` | 120000 / 4000000 | 脳の容量上限 |

育てるのが待ちきれないときは、自分のチャットログや好きな文章を
1 行 1 発話のテキストにして `/teach` で流し込むのが手っ取り早いです
(`tools/corpus_sample.txt` が例)。

## 6. 今どこまでできていて、どこからができていないか

できていること:

* ゼロから語彙・文法・話題のつながりを獲得し、段階的に喋りが伸びる
* 過去の会話の流れを思い出して文脈に沿った返事をする
* 知らない言葉を聞き返し、答えを学習に取り込む
* 自分でネットを調べ、拾った語彙で話題を広げる
* 放置中も夢を見て、Lv.4 以降は自分から話しかけてくる
* 差分永続化により、いつ落としても続きから再開できる
* **述語項構造を取り、肯定と否定を区別する**
* **教わった事実を一度で覚え、聞かれたら答え、訂正を受け付け、矛盾を指摘する**
* **同じ格スロットを埋める語を「似ている」と判断し、未知の遷移を補間する**
* **自分の理解度を測り、それを成長のゲートにする**

できていないこと:

* **現象的な意味理解ではありません。** 測れる軸での振る舞いの意味論であり、
  長い文では今も破綻します。世界の事実は知らず、知っているのは
  「あなたが言ったこと」だけです。
* **照応が解けません。**「それ」「さっきの」が何を指すかは追えません。
* **意図の分類**（質問／依頼／雑談の区別）はまだ暗黙的です。
* **接地がありません。** 語と実世界（時刻・PC の状態）の対応は未実装で、
  「今何時？」には答えられません。
* **述語を先に決めてから項を埋める生成**（plan-then-realize）は未実装で、
  生成は今も左から右への確率的な歩みです。破綻が残る主因はここです。
* **小型ニューラル言語モデル**への引き継ぎ（held-out perplexity で
  n-gram と交代させる構想）は未着手です。
* 数万ターン規模で何が創発するのかは、まだ誰も見ていません。
  `tools/grow_sim.py` はそれを観測するための道具です。

`legacy/netnavi_engine.py` に元記事のコアエンジンを置いてあります。
同じ会話を両方に与えると、何がどう変わったかが見えます。
